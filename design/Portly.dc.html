Popover design spec

Portly — menu-bar popover

Portly rejects the dark-dashboard default most dev tools reach for. A menu-bar popover isn't a dashboard — it's a glance. The interface borrows from macOS's own system UI: popover chrome, SF Pro, 4px geometry, and restraint. Nothing here is decorative: no gradients, no glass, no color used as costume. One accent, a grass green pulled from terminal "listening" conventions, appears only on focus rings and the active count, never as branding. Status reads through shape — filled dot, ringed dot, outline square, dashed ring — not hue alone, so it survives grayscale and colorblindness. Rows run tight, two lines each, with tabular numerals locking every port and uptime into a column a developer can scan without reading. Destructive actions stay invisible until hover, so the resting list stays calm. The result should feel less like a product and more like a well-labeled utility drawer — something Apple could have shipped, if Apple shipped ports.

Interaction spec

Keyboard. ⌘K focuses search from anywhere. ↑↓ move the highlight (wraps at ends). ⏎ opens the highlighted row's URL (no-op if non-HTTP). ⌫ starts kill-confirm on the highlighted row; ⌫ again confirms, Esc cancels. Esc with search focused clears it first, then dismisses the popover.

Confirm vs. instant. Kill always confirms — it's destructive and irreversible. Open, copy URL, and reveal-in-Finder are instant — they're read-only.

Kill animation. Confirmed kill fades the row to 0 opacity while its max-height collapses to 0 over 220ms, then the row is removed and the list reflows — no layout jump before the collapse starts.

Refresh without losing place. On rescan, rows are matched by port+PID, not index. Matched rows update in place; a row whose PID changed (process restarted) gets a brief 1px accent-colored underline for 2s instead of moving; only genuinely new or gone rows enter/exit the list. The keyboard highlight follows its row, not its position.

Signal design — no legend, no color dependency

HTTP — filled dot
HTTPS — ringed dot
Non-HTTP — outline square
Unresolved owner — dashed ring

A killed listener drops its glyph entirely and gets a flat line instead — "ended" is a fourth, distinct shape, not a faded copy of "running." Every signal is rendered in the same ink color as body text; nothing here depends on hue. Screenshot this in grayscale and it still reads.
